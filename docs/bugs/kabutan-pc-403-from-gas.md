# 株探PC版の個別ページが GAS から HTTP 403 になる

## 症状

「銘柄データ更新」が完了しても、`pickup` の注意列が全件「財務取得失敗（HTTP 403）」になった（2026-11-22、日曜）。

## 原因

株探PC版 `kabutan.jp/stock/finance?code=` が、GAS（Google のサーバー）からの取得に 403 を返していた。

- 手元の PC から curl で取ると、単発でも10並列でも 200 が返り、表も含まれていた。そのため、ページの仕様変更や休日が原因ではない
- 業種一覧のスマホ版 `s.kabutan.jp/sectors/` は、同じ GAS から取れていた
- 推測: 株探が PC 版だけ、データセンターの IP や大量アクセスを弾いている。同時取得（fetchAll）が引き金かどうかは切り分けていない
- 出来高の取得元 PC 版 `kabutan.jp/stock/kabuka?code=` も同じく 403 だったと考えられる（未確認）。その場合、出来高はすべて「不明」になり、出来高フィルタが効いていなかった

## 対処

取得元をスマホ版に切り替えた。

- 財務: `s.kabutan.jp/stocks/<コード>/finance/`。通期業績表の列の並びは PC 版と同じで、予想行は `<th class="sticky">予 2027.03</th>`、数値には「円」が付く
- 日足: `s.kabutan.jp/stocks/<コード>/historical_prices/daily/`。直近31営業日があり、日付の行は `<th class="sticky">11/20</th>`、出来高は最後の `<td>` で「株」が付く
- パーサは PC 版とスマホ版の両方の形を読む。実ページ（トヨタ）で、PC 版と同じ「減益予想 -7%」と配当性向 32.9% になることを確認した
- 失敗理由（HTTP コード、表なし、通信エラー）を注意列に出すようにした。次に弾かれたときもシートを見れば分かる

## 再発防止・注意

- スマホ版も弾かれ始めたら、まず同時取得数 `FETCH_BATCH_SIZE`（10）を下げて、並列が原因か切り分ける
- 株探のスマホ版は HTML 構造が変わりやすい（Tailwind のクラス名が並ぶ）。パースが全件「表なし」になったら構造変更を疑う
