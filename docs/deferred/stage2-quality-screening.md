# 第2段階スクリーニング（稼ぐ力×割安）— 先送り仕様

2026-11-22 に設計だけ確定し、実装は先送りしたもの。第1段階（業種一覧ページでの
ミックス係数・配当利回り・予算フィルタ）だけでは「今の稼ぐ力がしっかりしているのに
割安」な銘柄と、業績悪化途中で安く見えるだけのバリュートラップを区別できないため。

## 第1.5段階（流動性フィルタ）は実装済み（2026-11-22）

第1段階の通過銘柄だけに、株探の日足ページ `https://s.kabutan.jp/stocks/XXXX/historical_prices/daily/`
（PC版 `kabutan.jp/stock/kabuka` は GAS から 403。[bugs/kabutan-pc-403-from-gas.md](../bugs/kabutan-pc-403-from-gas.md)）
から直近25営業日の平均出来高を取得し、`settings` の `minAverageVolume`（初期値10,000株）
以下を除外する。単日の出来高はブレが大きいため平均を使う。
取得失敗・5営業日未満の銘柄は落とさず「不明」として残す。

制約: 出来高のキャッシュ（銘柄単位・1時間）は `clearAllCache` の対象外。
GAS の CacheService ではキーの列挙ができないため。実害は最大1時間古い出来高で
判定すること。第2段階でも銘柄単位キャッシュを増やす場合は同じ制約が付く。

## 配当の持続性チェックは実装済み（2026-11-22）

出来高フィルタの後の候補だけ、株探の財務ページの通期業績表（ヘッダーに「修正1株配」が
ある最初の表）を読み、次を pickup の「注意」列に書く。**除外はしない**（ユーザー判断）。

- 予想配当性向（予想1株配÷予想1株益）が `settings` の `maxPayoutRatio`（既定70%）超
- 予想赤字、減配予想（予想1株配 < 前期実績）、過去の減配（実績の1株配が前年割れ）
- 減益予想（予想最終益 < 前期実績の最終益）

分かっている限界:

- 業績修正の直近の履歴（上方・下方の矢印）は株探プレミアム限定で、無料ページでは古い期しか
  見えない。そのため下方修正の直接検知はせず、「減益予想」で代用している
- 記念配当・特別配当は区別して載っていないため判定できない。前期に跳ねて今期予想で戻る形は
  「減配予想」として拾える
- 財務のキャッシュ（業績行のみ、銘柄単位・6時間）も `clearAllCache` の対象外
- 金融4業種は除外せず、注意列の先頭に「金融業」と書いて区別している

残りの判定項目（ROE、営業赤字の有無、営業CF、自己資本比率など）は下記の設計のまま先送り。

## やり方（2段階にする理由）

全上場銘柄の財務ページを舐めると GAS の実行時間（6分）とリクエスト数の制限に当たる。
第1段階で数十件まで絞ってから、その候補だけ個別財務ページを取得する。

- 取得先候補: 株探の個別財務ページ。GAS からはスマホ版 `https://s.kabutan.jp/stocks/XXXX/finance/` を使う
  （PC版 `https://kabutan.jp/stock/finance?code=XXXX` は GAS から 403。2026-11-22 に PC 版で実在を確認。売上・営業益・経常益・最終益・1株益・1株配の推移、
  ROE・ROA・営業利益率、営業CF・フリーCF、自己資本比率・有利子負債倍率が取れる）
- 失敗した銘柄は「判定不能」として落とさず、第1段階の結果にフラグ付きで残す

## 判定項目（案）

| 観点 | 項目 | 目安 | 狙い |
|---|---|---|---|
| 稼ぐ力 | ROE（直近＋5年平均） | 8%以上 | 低PBRでも稼げていない銘柄を落とす |
| 稼ぐ力 | 営業利益率 | 業種内中央値以上 | 絶対値だと業種差で誤判定するため相対比較を基本にする |
| 安定性 | 過去5年の営業赤字回数 | 0回 | 単年の特益・好市況で安く見える銘柄を落とす |
| 安定性 | 5年売上・営業益の増減 | 減少トレンドでない | 右肩下がりの「安いには理由がある」を落とす |
| 利益の質 | 営業CF が純利益を上回る年数 | 5年中3年以上 | 会計上の利益だけで現金が伴わない銘柄を落とす |
| 健全性 | 自己資本比率 | 40%以上（金融は例外） | 借金で ROE を吊り上げた銘柄を落とす |
| 配当の持続性 | 配当性向 | 70%以下、かつ減配が続いていない | **実装済み**（注意列に表示。上記参照） |
| 割安（補助） | PEG（PER÷益成長率）、業種内 PER/PBR 順位 | PEG 1以下など | ミックス係数の単独判定を補強する |

閾値は `settings` シートの「第2段階・予約」行に置いてある（`minRoe` など）。
まず全てを足切りにはせず、観点ごとに点数を付けて合計スコア順に並べる方式を推す。
足切りを重ねると候補が0件になりやすく、どの条件で落ちたかも見えなくなるため。

## 今やらない理由 / 再開条件

- 理由: 財務ページの HTML 解析は構造変更に弱く、検証なしに入れると第1段階ごと壊しかねない。まず settings 化と予算フィルタ（実装済み）で運用を回す
- 再開条件: 第1段階の結果を数回眺めて「明らかに業績が落ちている銘柄が混ざる」と実感したとき。または候補件数が安定して数十件以下に収まると分かったとき
- 着手時は財務ページ1銘柄分の HTML フィクスチャで単体テストを書いてから解析を入れる
