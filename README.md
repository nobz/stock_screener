# invest-tool（銘柄スクリーニング）

「今の稼ぐ力はあるのに割安」な銘柄の候補を、Google スプレッドシート上で絞り込むための Google Apps Script 製ツール。株探（kabutan.jp）をスクレイピングし、割安・高配当・予算内・流動性の条件で候補を抽出して `pickup` シートに並べる。

## 使い方

1. 対象のスプレッドシートを開く（スクリプトは clasp でデプロイ済みのものが動く）
2. メニュー「株価取得」→「settingsシートを開く」で `settings` シートを確認する。C列の値を変えると次回更新から反映される
3. メニュー「株価取得」→「銘柄データ更新」を実行する。結果は `pickup` シートに出力される（割安な順＝ミックス係数の小さい順）。同時に候補が `history` シートへ追記される
4. 「注意」列を確認する。配当性向が高い、減配予想、減益予想、金融業などの理由が書かれる。注意がある銘柄も除外はしないので、最終判断は決算短信などで確認する
5. 銘柄名をクリックすると Yahoo!ファイナンスの銘柄ページが開く
6. settings の値だけを変えて試したいときは「キャッシュで再判定（取得しない）」を使う。ネット取得を一切せず、キャッシュ済みの生データに新しい閾値だけを適用して `pickup` を作り直すため速い。この実行は `history` に記録しない

補足:

- 「キャッシュで再判定」はキャッシュが残っている間（最大1時間）だけ使える。データが無ければその旨を表示するので、その場合は通常の「銘柄データ更新」を先に実行する。一部ページだけキャッシュ切れの場合は結果が欠ける可能性があり、ログに注意が出る
- 判定ロジックや閾値を変えた直後は、メニュー「キャッシュクリア」を実行してから更新する（業種ページのキャッシュが最大1時間残るため。settings の変更だけなら生データキャッシュ方式なのでクリア不要）
- 実行中は右側のサイドバーにプログレスバー・経過秒数・処理中の段階が出る。終わると結果の要約（候補件数、注意ありの件数）が表示されるので「閉じる」で閉じる。サイドバーを途中で閉じても処理は続く（ただし下記の「続きの自動実行」はサイドバーが開いている間だけ働く）
- GAS の1回の実行は6分まで。キャッシュが空の初回など時間がかかるときは、4分半で一旦区切り、サイドバーが自動で続きを実行する（「2回目」などと表示される）。取得済みの分はキャッシュから読むので続きから進む

## 判定条件

| 段階 | 条件 | 既定値 | 備考 |
|---|---|---|---|
| 第1段階 | グレアム・ミックス係数（PER×PBR）が上限未満 | 11 | PER/PBR が欠損している銘柄は判定不能として除外 |
| 第1段階 | 配当利回りが下限以上 | 3.5% | |
| 第1段階 | 株価×単元株数が予算上限以下 | 300,000円（=株価3,000円以下） | 値がさ株の除外が目的 |
| 第1.5段階 | 直近25営業日の平均出来高が下限超 | 10,000株 | 候補だけ時系列ページを追加取得。取得失敗・日数不足は「不明」として落とさない |
| 注意表示 | 予想配当性向が上限超、予想赤字、減配予想、過去の減配、減益予想、金融業 | 配当性向70% | 除外せず「注意」列に書く。候補だけ財務ページを追加取得 |
| 第2段階 | ROE・営業利益率・自己資本比率など | 未実装 | 設計は [docs/deferred/stage2-quality-screening.md](docs/deferred/stage2-quality-screening.md) |

減益予想は「今期の会社予想の最終益が前期実績より少ない」ことを示す。業績の下方修正の履歴は株探プレミアム限定で取れないため、その代わりの目安として使っている。記念配当・特別配当は判定できない。

## 出力シート

| シート | 内容 |
|---|---|
| `pickup` | 最新の候補。列はコード、名称、業種、株価、前日比、騰落率、PER、PBR、配当利回、ミックス係数、購入金額（単元）、出来高（25日平均）、予想配当性向、注意 |
| `history` | 通常実行のたびに候補を追記する履歴。適用した settings を JSON で残し、後で成績を比べる土台にする（成績の計算は未実装。[docs/deferred/performance-tracking.md](docs/deferred/performance-tracking.md)） |
| `settings` | 判定の閾値 |

## settings シート

C列の値だけを編集する。キーが不足している場合は実行時に自動で末尾へ追加される。設定名（B列）と説明（D列）はコードの定義に合わせて自動更新されるが、値（C列）は上書きされない。

| キー | 設定名 | 初期値 |
|---|---|---|
| `maxBudgetPerStock` | 1銘柄の予算上限（円） | 300000 |
| `unitShares` | 単元株数 | 100 |
| `grahamMixThreshold` | グレアム・ミックス係数の上限 | 11 |
| `dividendYieldThreshold` | 配当利回りの下限（％） | 3.5 |
| `minAverageVolume` | 25日平均出来高の下限（株） | 10000 |
| `maxPayoutRatio` | 予想配当性向の上限（％）。超えると注意列に書く | 70 |
| `minRoe` ほか2項目 | 【第2段階・予約】 | 未適用 |

## 技術スタック

| 領域 | 採用 |
|---|---|
| 実行環境 | Google Apps Script（V8 ランタイム） |
| データ取得 | 株探のスクレイピング（`UrlFetchApp`＋正規表現パース）。すべてスマホ版の `s.kabutan.jp` で、業種一覧 `sectors/`、日足 `stocks/<コード>/historical_prices/daily/`、財務 `stocks/<コード>/finance/`。PC版 `kabutan.jp/stock/...` は GAS から HTTP 403 になる |
| キャッシュ | `CacheService`（業種ページの生データ1時間、出来高は銘柄単位1時間、財務の業績行は銘柄単位6時間） |
| デプロイ | clasp（`clasp push --force`）。送信ファイルは `.claspignore` で限定 |
| テスト | Node.js 標準テストランナー（`node --test`）。GAS のグローバルをモックして `.gs` をそのまま読み込む |

ファイル構成:

| ファイル | 役割 |
|---|---|
| `stock_screener.gs` | 本体。設定読み込み、スクリーニング、シート出力 |
| `finance.gs` | 株探から株価を取得するユーティリティ |
| `progress.html` | 実行中の進捗を表示するサイドバー |
| `tests/quality_fixes.test.js` | 回帰テスト |
| `appsscript.json` | GAS マニフェスト |
| `docs/` | 不具合記録・先送り仕様・作業日誌（索引は [docs/README.md](docs/README.md)） |

## 開発手順

```powershell
# テスト
node --test tests/quality_fixes.test.js

# デプロイ前に送られるファイルを確認する
clasp show-file-status

# デプロイ
clasp push --force
```

- `.gs` や `.html` ファイルを増やしたら `.claspignore` にも追記すること。テストファイルが GAS に送られるとスクリプト全体が読み込みエラーになる。詳細は [docs/notes/clasp-push.md](docs/notes/clasp-push.md)
- パース処理を変えるときは、実ページの HTML を取得して構造を確認してから直すこと（株探の HTML は予告なく変わる）

## 制約・注意

- 株探は非公式なスクレイピングであり、HTML 構造の変更で突然動かなくなる可能性がある
- GAS の実行時間は6分まで。全銘柄ではなく候補に絞ってから個別ページを取得する設計はこのため
- 出来高と財務のキャッシュは「キャッシュクリア」の対象外（GAS ではキャッシュキーを列挙できないため）。実害は出来高が最大1時間、業績が最大6時間古いまま判定すること
- 候補ごとに時系列ページと財務ページを追加で取得するため、初回は6分制限を超えうる。その場合は区切って続きを自動実行する（[docs/bugs/execution-time-limit.md](docs/bugs/execution-time-limit.md)）。スクリプトエディタから直接実行したときは自動で続かないので、もう一度実行する
- このツールは候補の抽出までを行い、売買の判断や注文は行わない
